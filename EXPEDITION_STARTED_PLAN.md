## 2. Текущее поведение и почему нужны изменения

### 2.1. Модалка участия

`src/components/shared/RequestModal.tsx` сейчас всегда показывает форму:
- выбор экспедиции;
- имя;
- телефон;
- email;
- consent;
- кнопку «Оставить заявку».

Нужно добавить третье состояние — `started`, в котором правая панель заменяется контактным блоком.

### 2.2. «Ближайшие экспедиции»

`src/components/sections/FeaturedMarkets.tsx` использует `getNearestExpedition`, а эта функция завязана на `timer.enabled` и `timer.targetDate`.

Проблема:
- у ЮАР таймер истекает 15 ноября;
- у Вьетнама `timer.enabled: false`;
- после 15 ноября `getNearestExpedition` вернёт `undefined`;
- `FeaturedMarkets` делает `if (!nearest) return null` — **блок вообще исчезнет**, а не переключится на Вьетнам.

### 2.3. Статическая главная

Главная сейчас статическая. `Date.now()` внутри серверного компонента считается на этапе сборки. Если не сделать отдельный клиентский пересчёт, блок «Ближайшие экспедиции» может остаться с ЮАР после 21 ноября до следующей пересборки.

### 2.4. Дублирование карточек

Сейчас правая часть строится как `[vietnam, ...upcoming]`. После 21 ноября, когда Вьетнам станет левой карточкой, он же останется первой правой карточкой. Нужно исключать текущую экспедицию из правого списка.

### 2.5. Завершённая страница

При переводе ЮАР в `completed`:
- страница перейдёт на шаблон завершённой экспедиции;
- fallback заголовка сейчас — `Экспедиция в ${country} 2025`, для ЮАР 2026 это будет ошибкой;
- `recapMedia` пока может отсутствовать — компонент просто не отрендерится;
- отзывов и статистики может не быть — страница будет минимальной, но не сломается.

### 2.6. Шапка на завершённой странице

Сейчас кнопка «Стать участником» в шапке показывается на любой странице экспедиции после скролла. Если ЮАР станет `completed`, кнопка может открыть форму для завершённой экспедиции. На завершённой странице её нужно скрыть.

### 2.7. `/form`

`LeadForm` использует `getNearestExpedition` и `activeExpeditions[0]`. После перевода ЮАР в `completed` страница `/form` начнёт предвыбирать Вьетнам. Это согласовано, `/form` не меняем.

| Дата и время | Что происходит |
|---|---|
| **16.11.2026, 10:00 МСК** | Участие в ЮАР закрывается: модалка переключается в контактный режим |

## 4. Модель состояний

### 4.1. Состояние участия

| Условие | Что показываем |
|---|---|
| `status: completed` | Архив, модалка участия не нужна |
| `status: upcoming` | Обычная форма «Оставить заявку» |
| `active`, сейчас < `participationClosesAt` | Обычная форма «Стать участником» |
| `active`, сейчас >= `participationClosesAt` | Контактный режим «Экспедиция началась» |
| Дат нет / некорректны | Обычная форма, как сейчас |

Для ЮАР:
- `startDate: '2026-11-15'`;
- `endDate: '2026-11-21'`;
- `participationClosesAt: '2026-11-16T10:00:00+03:00'`.

После `endDate` и до ручного перевода в `completed` страница может оставаться активной, но модалка уже должна показывать контакты, а не форму.

### 4.2. Состояние блока «Ближайшие экспедиции»

| Условие | Что слева |
|---|---|
| Есть активная экспедиция, которая идёт сейчас | Она |
| Иначе — ближайшая будущая активная | Она |
| Иначе — ближайшая датированная upcoming | Она |
| Иначе — первая активная/upcoming по данным | Она |

Для ЮАР:
- до `2026-11-22T10:00:00+03:00` — ЮАР;
- после — Вьетнам.

Правые карточки:
- берём Вьетнам + upcoming, как сейчас;
- исключаем экспедицию, которая уже показана слева;
- ограничиваем тремя карточками;
- после 22.11 это будут 3 upcoming.

## 9. Риски и краевые случаи

- **Статическая сборка:** дата может застыть на билде. Решение — клиентский пересчёт в `FeaturedMarkets` и в модалке.
- **Hydration mismatch:** начальный рендер должен быть одинаковым на сервере и клиенте. Решение — детерминированный fallback + пересчёт после монтирования.
- **Рассинхрон 22.11:** статус `completed`, таймер Вьетнама и переключение главной делать одновременно в 10:00.
- **Дублирование Вьетнама:** исключать текущую экспедицию из правых карточек.
- **Завершённая страница:** не забыть `recapTitle` для 2026 года.
- **Шапка на завершённой:** скрыть кнопку участника, иначе откроется форма для завершённой экспедиции.
- **`/form` после завершения:** предвыберет Вьетнам — согласовано.
- **Таймер Вьетнама раньше времени:** если включить до 22.11, countdown может появиться раньше.
- **Модалка через полночь:** проверять состояние перед отправкой, чтобы не принять заявку после закрытия.
- **Пустой селект:** если открытых экспедиций нет, показывать контакты, а не пустую форму.
