# Контекст проекта FExperience — для ИИ-агентов

> Бортовой журнал: что за проект, как мы работаем, какие решения приняты и почему.
> Прочитай этот файл + `DEPLOY.md` + `fexperience/todo.md` перед любой задачей.
> Без секретов — можно хранить в репо.

## 1. Что это

Редизайн сайта бизнес-экспедиций Forbes: `fexperience/` — Next.js 16.2.4 + React 19 +
Tailwind v4 (CSS-first, без `tailwind.config`), TypeScript strict. Прод:
`https://fexperience.forbes.ru`, хостинг RelaxDev (Vercel-like, автодеплой из git),
деплой-репо `CharkiSPB/FExperienceDeploy` (структура: `fexperience/` в корне).
Рабочий синк между компьютерами — `CharkiSPB/FExperienceRediz`.

Структура `src/`: `app/` (App Router: `page`, `about`, `expeditions/[slug]`,
`articles/[slug]`, `api/lead`), `components/{sections,layout,shared,maps,ui}`,
`data/` (Source of Truth: expeditions, regions, speakers, program…),
`lib/mail.ts` (nodemailer), `lib/mdx.ts` (статьи из локальных `.mdx`).

## 2. Как мы работаем (договорённости из практики)

- Язык общения — русский, ответы короткие, по делу, без воды.
- Команды «изучи, ничего не делай» = только чтение. Правки — только по явной команде.
- Проверка обязательна: `tsc --noEmit`, `npm run build`, скриншоты Playwright
  (dev-сервер + programmatic screenshots, не «посмотри глазами»).
- Git аккуратно: на ветке `redesign` НИКОГДА `git add -A` (рядом лежит untracked
  `files3/` — спеки, уедут в публичный деплой-репо). Точечно: `git add fexperience/...`.
- Пуш в `main` деплой-репо = мгновенный прод. Сначала `redesign` → превью → проверка → прод.
- После каждого визуального фикса — скрин до/после (360/1280/1440 минимум).
- Dev-серверы: гасить зомби-процессы node после себя (иначе висят порты 3100+ и
  снимаешь СТАРЫЙ код — было трижды). Проверка «что отдаёт сервер» — через
  `Invoke-WebRequest` + computed styles, не верой.
- Пользователь смотрит свой dev — ему всегда напоминать `Ctrl+F5` (кэш CSS/картинок).

## 3. Дизайн-система (факты, не вкусы)

- Бумага `#F9EEE5/#F1E3D8/#FFF8F3`, бренд `#FF6B2C → #B7410E`, шрифты:
  Philosopher (под `--font-playfair`), HelveticaNeueCyr, Good Vibes Pro (рукопись).
- Весь визуал — `src/app/globals.css` (~5200 строк). Tailwind — только утилиты,
  кастом — plain CSS. Дубли токенов и `!important` местами — историческое, не чинить без нужды.
- Desktop-first брейкпоинты `max-width: 1024/767/640` (+ `900`, `639` местами).
  Скейл `1024–1280: html{font-size:14px}` — не трогать.
- Стекло: `rgba(255,255,255,.05–.62)` + `blur(14–22px)`; бумажный нойз `body::before z-40`.
- Анимации появления — `.fade-up` + `useScrollReveal`; для скриншотов докласс `visible`
  и снос прелоадера через evaluate, иначе splicing показывает пустоты.

## 4. Журнал решений (что → почему)

- **Маска hero деталки**: было два слоя (маска + overlay) с разными концами → видимый шов.
  Правило: переход ОДНИМ слоем. Финал: eased-маска
  `transparent → .10/.38/.68/.88 → #000` (быстрый набор, мягкая посадка).
- **Точки «Что включено»**: якорь перенесён с текста на колонку (`li::after`),
  иначе при разной длине строк точки пляшут. Центры колонок = центры панелей коллажа:
  ширины колонок замерены по белым разделителям фото (`25.5/18.3/13.5/14.5/17.8/10.4%`),
  `gap: 0` (любой gap ломает привязку). Ряд вынесен из контейнера на всю ширину —
  картинка full-bleed, иначе системы координат не совпадают.
- **Переносы ровно в 2 строки**: делает `splitTwoLines()` в компоненте (половина по символам),
  НЕ CSS (`max-width: Nch` давал 3 строки). Работает для любых будущих пунктов.
- **Мобильный таймлайн**: картинка `display:none`, вертикальная линия + точки слева.
  Баг: `display:none` планшета перебивал мобильное (та же специфичность) — лечится явным
  `display:block`. Проверять computed, не файл.
- **Печати (6 шт.)**: текст длиннее окружности → «FEXPE». Фикс `textLength=465/478` +
  `lengthAdjust="spacing"` во всех печатях сразу (Hero, деталка, about, каталог, платформа, модалка).
- **Теги вместо пилюль**: классы не переименовывали (минимум диффа), lowercase через CSS
  (данные целы), `#` отдельным спаном оранжевым.
- **Футер-подписка**: была локальной заглушкой → новый `formType:'subscribe'` в `/api/lead`,
  тема «Новая подписка: email». Без чекбокса согласия (дизайн не трогали) — для строгого
  152-ФЗ добавить позже.
- **RequestModal не слал письма**: отправка была закомментирована «для демо» с фейковым
  успехом. Включили реальный `fetch` + маппинг в схему `participant`. Диагностика таких
  «отправляется, но не приходит» — всегда сначала читать `onSubmit`.
- **Поле подписки схлопывалось (19px)**: виноват `flex-1` во flex-колонке (перебивает height).
  Фикс `flex-none sm:flex-1` + фиксированная высота под кнопку (38px). Проверять computed.
- **Фото команды**: бокс `3:4` + `object-position: top` + `quality={90}` (штриховка сыплется
  на q75) + персональный `photoScale` через CSS-переменную (ховер preserved через calc).
  Зум без `overflow:hidden` на боксе лезет на текст — было, починили.
- **Позиция/отзывы паддинги**: режем паддингами секций, не маржинами внутренностей.
- **Табы программы на мобильных**: `overflow-x:auto` + mask-фейд справа как affordance.
- **Методология about**: итог — сетка `1fr 2fr` (текст слева, фото справа на месте двух колонок),
  чеклист удалён полностью (данные + CSS + импорт иконки).

## 5. Безопасность (применено, коммит `ccf1147`)

`clean()` против header injection в subject + `esc()` для HTML-тела письма;
zod `.max()` везде + `maxLength` на инпутах; in-memory rate limit 10/IP/10мин на `/api/lead`;
webhook только `https://`; 400 отдаёт одно сообщение; SMTP `rejectUnauthorized: true`
(проверено живой отправкой); sitemap статей строится из реальных `.mdx`
(старый хардкод давал 404); 301 `/expeditions/new-delhi → /india`.
Сознательно НЕ делали: капчу, CSP (убьёт инлайн Метрики), санитизацию MDX
(актуально только при переезде на CMS — там включить `rehype-sanitize`).

## 6. Git-история (чтобы не пугаться)

- Локальные `1commit/2commit` + `rediz/main` (12 коммитов со второго ПК) смержены:
  шум от `100644→100755` и CRLF/LF — лечится `core.fileMode false`, содержательных
  конфликтов было ~30 (в основном 1 ханк). Стратегия: брать их сторону целиком,
  своё (домены) — точечно. Проверка: `git diff --ignore-cr-at-eol`.
- `F_logo.svg` после мержа содержал маркеры `<<<<<<<` (печати без «F») — после любого
  мержа грепать маркеры по `src` И `public`.
- `add/add`-конфликты бинарников → брать `--theirs` (их версии новее).
- Ветки: `redesign` (превью/работа), `main-backup` (слепок прода), тестовые чистить
  только после стабильного прода. Коммиты — imperatives на русском, точечный `add`.
